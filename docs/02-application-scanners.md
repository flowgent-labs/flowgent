# Application Layer: Enterprise Security Vulnerability Remediation (Layer 2)

## 1. Overview
This layer utilizes the Generic Orchestration Engine (Layer 1) to drive a team of highly specialized AI Agents. Unlike a single "Magic Agent", this system employs a **Multi-Agent Team** approach to handle real-world enterprise vulnerabilities (CVEs) across the entire Software Development Life Cycle (SDLC).

## 2. Enterprise Agents Team

### 2.1 Supervisor Agent (The Manager)
- **Instances**: Multi-instance. Triggered dynamically by events (e.g., one instance per Repo).
- **Role**: Orchestrates the end-to-end lifecycle, enforces policies, creates Pull Requests (PRs), and monitors CI/CD loops until all issues are green.

### 2.2 Discover Agent (The Scout)
- **Role**: Parallelizes the fetching of scan results from various enterprise systems via their specific MCPs. Gets deep-dive issue links and logs.
  - *Inputs:* Repo URL, PR Number, Latest Commit SHA.
  - *Outputs:* Structured Issue Links for Build/Test, DAST/SAST/CONT, FOSS, and Code Style.

### 2.3 Alpha Agent Group (The Solvers)
Specialized agents solving specific issues in **parallel**.
- **Type A: Build/Test Alpha** (Fixes broken builds).
- **Type B: Cyberflow Alpha** (Fixes runtime/container vulnerabilities).
- **Type C: FOSS Alpha** (Fixes Vulnerable Dependencies via SonatypeIQ).
- **Type D: Code Quality Alpha** (Fixes SonarQube issues).

### 2.4 Review Board Agents (The Jury)
- **Role**: Multi-agent panel that votes on the code changes generated by Alpha Agents.

## 3. Detailed Orchestration Flow

### 3.1 Supervisor Trigger (Per-Repo)
Supervisor Agent instances run dynamically: `Supervisor(repo="org/repo-A")`. It initializes the orchestration context.

### 3.2 Discover Agent Parallel Fetching
Discover Agent calls GitHub, Cyberflow, SonarQube, SonatypeIQ MCPs simultaneously.
*Result*: Structured links for `build-test`, `dast/sast/cont`, `foss`, and `codestyle`.

### 3.3 Alpha Agents Parallel Resolution & Retrieval
Alpha Agents execute simultaneously based on the issue types. 

#### 3.3.1 Build-Test Alpha (Nexus/Build Issue)
If failure logs indicate a library is blocked/isolated (e.g., 403 in Nexus):
1. Calls `nexus3_mcp` to search Maven coordinates (`groupId:artifactId`).
2. Iteratively finds a newer version with `fallwall status=allow` (instead of deny).
3. Updates `pom.xml` with the best candidate version.

#### 3.3.2 Cyberflow Alpha (DAST/SAST/CONT)
For custom security scans: Autonomously uses `web_search_mcp` to find industry solutions for the specific CVE or exploit pattern identified in the logs.

#### 3.3.3 FOSS Alpha (Dependency Vulnerabilities)
Scans SonatypeIQ results:
- If `upgrade_path` is provided: Automatically apply the exact suggested version.
- If `no_upgrade_path` exists: Calls `iq_mcp` to execute **add_waiver (30-days)**, obtaining an exception approval to bypass the blocker.

#### 3.3.4 SonarQube Alpha (Code Quality)
Reads CodeSmell/Issue details and uses `web_search_mcp` to find industry code refactoring solutions.

> *State Compression*: At the end of each Alpha execution, the detailed logs and patches are compressed into a concise summary and saved to `Memory (SQLite/Vector)` for resilience.

### 3.4 Review Multi-Agents (3-Round Voting)
All changes are sent to 3 `Reviewer Agents`. 
1. **Vote**: They iterate up to 3 rounds to decide if all fixes are reasonable.
2. **Re-route**: If rejected, they send specific feedback back to the offending Alpha Agent for rework.
> *State Compression*: Voting results and updated task progress are strictly persisted before proceeding.

### 3.5 Supervisor PR Submission
Supervisor Agent collects the approved patches and commits the code.
- **Configuration**: `pr_strategy` (default: `separate_new_pr`, alternative: `merge_into_biz_pr`).
> *State Compression*: Submission status is persisted.

### 3.6 CI Verification Loop
Supervisor waits for GitHub CI to run. 
1. Periodically fetches the latest commit's `all scans` status.
2. **If Green**: Generates a final Markdown report (`scan_summary.md`) containing: Issue description, Scan link, and the applied Fix Methodology.
> *State Compression*: Final CI state is persisted.

### 3.7 Notification Delivery
The Supervisor invokes the **Abstract Notification Interface** to send the final report (Step 3.6) via Email, DingTalk, or Slack.
