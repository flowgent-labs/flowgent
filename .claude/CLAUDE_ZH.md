# 项目约定

## 代码质量

- 目录和文件命名保持收敛、一致，避免随意新增目录或文件
- 遵循 Go 语言命名规范（包名小写、导出符号大小写、接口以 er/or 结尾等）
- 尽量抽象统一的 interface，面向接口编程，减少具体类型耦合
- 遵循高内聚低耦合：模块内部逻辑紧密，模块间通过接口交互

## 测试代码组织

- **禁止**在 `src/` 正式代码目录下写任何测试文件或测试辅助文件
- **唯一例外**：Go 标准的单元测试，文件名与主代码相同且以 `_test.go` 结尾，可与主代码放在同一目录
- 所有 E2E / 集成测试（需要连接中间件的自动化测试）写在 `tests/` 目录中：
  - 基础/共享的测试代码抽到 `tests/testutil/`，保持抽象和规范
  - 不同模块的 E2E 或场景测试，文件命名采用 `01-xxx` 格式
  - 编号按系统模块内部执行顺序编排，便于按序阅读和理解

## 成本控制

- 任何大规模递归探索或批量读取源码文件的操作，**一律委派给 subagent**（如 Explore agent 或小模型的 general-purpose agent）
- 这类脏活不需要高智力，卸载给子代理可降低 API 成本，同时保护主对话上下文质量
